# 작업 선택

먼저 저장소 루트의 `.agents/skills/team-common.md`를 읽는다.

1. 사용자 선택 번호가 있어야 한다. 없으면 목록을 보여주고 선택을 기다린다. 계정·개인 브랜치를 확인한다.
2. 이슈를 새로 조회해 열린 상태·프로젝트 할 일·미할당·재현/완료 조건을 확인한다. ready 라벨은 요구하지 않는다. 설명이 부족하면 완료 조건을 묻는다. 다른 담당자는 변경하지 않는다. 본인만 이미 배정됐다면 기존 작업을 이어가고 댓글·배정을 반복하지 않는다. PR 병합 후 QA 대기인 작업도 현재 작업으로 유지한다.
3. 내 다른 진행 이슈나 열린 개인 PR이 있으면 새 선점하지 않는다. 병합 후 해결 확인 대기인 작업도 완료 전에는 새로 선점하지 않는다. 최신 main 미반영이면 team-sync 절차를 먼저 적용한다.
4. 배정 직전 담당자를 재조회하고 유효하면 `gh issue edit <번호> --repo 2026-tmax-it-school/nightmare --add-assignee @me`한다. 즉시 다시 조회해 담당자가 나 하나인지 확인한다. assign은 원자적 잠금이 아니다. 여러 담당자가 생기면 작업 시작·상태 변경을 멈추고 중복 선점을 알린다. 다른 담당자는 제거하지 않는다.
5. 배정 확인 후 프로젝트 카드를 작업 중으로 바꾸고 확인한 번호를 로컬 nightmare.team-issue에 저장한다. 상태 변경 실패는 배정 성공과 구분해 보고한다.
6. 브랜치·작업 범위의 시작 댓글을 한 번 남긴다. 같은 이슈에 같은 계정의 시작 댓글이 있으면 반복하지 않는다. 관련 코드·GDD를 읽고 완료 조건과 검증 방법을 안내한다. 이 호출만으로 기능 구현 전체까지 시작하지 않는다.
7. 특정 이슈 포기 요청이면 공통 인계 절차로 자기 assign·상태·무효한 로컬 이슈 설정을 해제한다.
