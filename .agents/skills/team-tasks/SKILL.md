# 할 일 보기

먼저 저장소 루트의 `.agents/skills/team-common.md`를 읽는다.

1. GitHub 계정·저장소를 확인한다. 목록만 볼 때 개인 브랜치 설정은 요구하지 않는다.
2. 열린 이슈의 번호·제목·body·assignees·labels·URL을 조회한다. 모든 페이지를 조회하거나 제한/누락 가능성을 표시한다. 닫힌 이슈와 PR은 작업 목록에 섞지 않는다.
3. ready이고 미할당이며 다른 진행 상태가 없는 이슈만 선택 가능 목록에 넣는다. 번호·제목·완료/재현 조건·실제 우선순위 라벨·링크를 보여준다. 난이도/우선순위는 추측하지 않는다.
4. ready가 없는 미할당 이슈는 “선생님/QA 정리 대기”로 별도 표시한다. 임의 라벨·배정은 하지 않는다.
5. 내 담당 이슈와 열린 개인 PR을 먼저 요약한다. 진행 작업이 있으면 이어가도록, 없으면 학생이 번호를 선택하도록 안내한다. Git 변경·assign·댓글·라벨 변경을 하지 않는다.
