# 할 일 보기

먼저 저장소 루트의 `.agents/skills/team-common.md`를 읽는다.

1. GitHub 계정·저장소를 확인한다. 목록만 볼 때 개인 브랜치 설정은 요구하지 않는다.
2. 프로젝트 이슈 카드와 열린 이슈의 번호·제목·body·assignees·labels·URL을 대조한다. 모든 페이지를 조회하거나 제한/누락 가능성을 표시한다. 닫힌 이슈와 PR은 작업 목록에 섞지 않는다.
3. 프로젝트의 할 일 칸에 있고 열린 미할당 이슈만 선택 가능 목록에 넣는다. ready 라벨은 요구하지 않는다. 번호·제목·완료/재현 조건·실제 우선순위 라벨·링크를 보여준다. 난이도/우선순위는 추측하지 않는다.
4. 보드 미등록/상태 미지정 이슈와 설명이 부족한 이슈는 별도 표시한다. 등록 요청을 안내하고 목록 조회만으로 보드를 수정하지 않는다. 설명이 부족하면 선점 시 필요한 완료 조건을 확인한다.
5. 내 담당 이슈와 열린 개인 PR을 먼저 요약한다. 진행 작업이 있으면 이어가도록, 없으면 학생이 번호를 선택하도록 안내한다. Git 변경·assign·댓글·라벨 변경을 하지 않는다.
