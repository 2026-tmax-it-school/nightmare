# QA 확인

먼저 저장소 루트의 `.agents/skills/team-common.md`를 읽는다.

1. 지정 이슈·PR의 링크, 담당자, 변경 범위, 재현 절차, baseRefName·mergedAt·mergeCommit을 확인한다. 잘못 연결된 이슈를 닫지 않는다. 번호가 없으면 작업 중 카드 중 main에 병합된 PR과 연결된 열린 이슈를 보여주고 선택을 기다린다.
2. 열린 PR은 사전 검증 가능하지만 이슈를 닫지 않는다. 미병합으로 닫힌 PR도 완료가 아니다. 사전 결과만 기록하고 main 병합을 기다린다.
3. main 병합 후에도 카드는 작업 중으로 유지하고 담당자를 보존한다. AI 코드 리뷰와 실제 플레이 확인을 구분한다. 코드 리뷰 액션 성공만으로 이슈를 닫지 않는다.
4. fetch한 origin/main의 정확한 SHA에 병합 결과가 포함됐는지 확인한다. 진행 중 checkout은 바꾸지 않고 필요하면 별도 임시 detached worktree를 쓴다. 별도 포트 서버의 URL이 해당 checkout인지 확인하고 생성한 임시 환경만 정리한다.
5. 이슈/PR 재현 절차와 주변 동작을 실제 실행한다. 브라우저를 못 쓰면 QA의 실제 결과를 받기 전에는 종료하지 않는다. 검증 SHA·환경·절차·실제 결과를 기록한다. 학생 브랜치 서버를 main 검증으로 착각하지 않는다.
6. 통과면 PR/이슈 상태를 재확인하고 검증 댓글을 남긴 뒤 해당 이슈만 completed로 닫고 프로젝트 카드를 완료로 맞춘다. 결과를 재조회한다. 이미 완료된 반복 요청은 댓글/종료를 중복하지 않는다.
7. 실패면 열린 상태로 유지하고 재현·실제 결과·SHA를 남긴다. 프로젝트 상태는 작업 중으로 유지하고 기존 담당자에게 후속 수정을 안내한다. 개인 브랜치에 다른 이슈의 열린 PR이 있으면 선생님이 순서를 정할 때까지 섞지 않는다. 명시적으로 재검증한 닫힌 이슈에서 같은 문제가 재현되면 근거를 남기고 다시 연 뒤 프로젝트 카드를 작업 중으로 복구한다.
8. 종료/실패/사전 확인/미검증 중 실제 결과와 링크를 보고한다. 이 스킬에서 코드 수정·commit·push·PR 병합은 하지 않는다.
