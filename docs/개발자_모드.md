# 개발자 모드

테스트할 때 처음부터 다시 플레이하지 않고 원하는 시점에서 바로 시작하는 기능입니다. 일반 플레이에는 영향이 없습니다.

## 켜는 법

로컬 서버(`python tools/serve.py`)를 띄운 뒤 주소 끝에 `?dev`를 붙입니다.

| 주소 | 동작 |
|---|---|
| `http://localhost:8123/?dev` | 타이틀 대신 **체크포인트 선택 화면** |
| `http://localhost:8123/?dev&start=<id>` | 해당 체크포인트에서 **바로 시작** (예: `?dev&start=chase1`) |
| `http://localhost:8123/?dev&debug` | 개발자 모드 + 화면이 가려져도 게임 루프 유지 (브라우저 자동 테스트용) |

`start=`로 바로 시작할 때도 "아무 키나 눌러 시작" 화면에서 키를 한 번 눌러야 합니다. 브라우저가 사용자 입력 전에는 소리를 막기 때문입니다. 없는 id를 넣으면 선택 화면에 "체크포인트 없음" 알림이 뜹니다.

## 조작

| 키 | 기능 |
|---|---|
| ↑ ↓ | 체크포인트 이동 (선택 화면) |
| E / Space / Enter | 선택한 시점에서 시작 |
| `` ` `` (숫자 1 왼쪽) | 플레이 중 언제든 체크포인트 선택 화면으로 복귀 |

목록 맨 아래 **타이틀 화면 (일반 시작)**을 고르면 평소처럼 타이틀부터 시작합니다.

| `rooftop` | 옥상 도착 (3장 시작) | 3장 배너, 단서 4개 조사, 옥상↔2층 계단 |

각 체크포인트는 그 시점까지 정상 플레이로 얻었을 플래그·단서·소지품·기억 조각을 미리 갖춘 상태로 시작합니다.

## 저장

개발자 모드의 저장은 별도 슬롯(`localStorage`의 `ithope_save_v1_dev`)에 기록되어 **실제 플레이 저장(`ithope_save_v1`)을 덮어쓰지 않습니다.** 개발자 모드에서 잡혀서 "추격 직전부터 다시"를 고르면 이 개발용 저장에서 이어집니다.

## 체크포인트 추가·수정

체크포인트는 [`data/checkpoints.json`](../data/checkpoints.json)에 정의합니다. 코드를 고칠 필요는 없습니다.

```json
{
  "id": "p2",
  "label": "1장 — P2 열쇠함 앞",
  "from": "frag1",
  "scene": "Explore",
  "map": "school1f",
  "flags": ["frag1", "read_logbook"],
  "clues": ["notebook", "logbook"],
  "fragments": [1],
  "pos": { "x": 15, "y": 15, "dir": "up" }
}
```

| 필드 | 설명 |
|---|---|
| `id` | `start=`에 쓰는 이름 |
| `label` | 선택 화면에 표시되는 이름 |
| `from` | 앞 체크포인트의 상태(플래그·단서·소지품·조각)를 이어받음. 체인으로 연결 가능 |
| `scene` | 시작 씬: `Explore`, `Cutscene`, `GameOver`, `DemoEnd` |
| `cutscene` | `scene`이 `Cutscene`일 때 `data/cutscenes.json`의 id |
| `map` | `scene`이 `Explore`일 때 맵 id |
| `flags` | 켤 플래그 목록 (값 `true`) |
| `set` | 값이 있는 플래그 (예: 추격 재개용 `pendingChase`) |
| `clues` / `items` / `fragments` | 추가할 단서·소지품·기억 조각 |
| `denial` | 부정 수치 (생략하면 0) |
| `pos` | 시작 칸 좌표와 바라보는 방향(`up`/`down`/`left`/`right`). 생략하면 맵의 기본 스폰 |

**주의:** 맵 배치나 스크립트의 플래그 이름이 바뀌면 이 파일의 좌표·플래그도 함께 고쳐야 합니다. 조사 대상 앞에서 시작하려면 그 오브젝트 바로 옆 칸을 `pos`로 주고 `dir`을 오브젝트 쪽으로 맞춥니다.
